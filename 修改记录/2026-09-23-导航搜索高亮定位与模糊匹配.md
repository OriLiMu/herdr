# 导航搜索高亮定位与模糊匹配

- **日期**: 2026-09-23
- **版本基线**: v0.9.1 (commit 065ef9d6)
- **涉及文件**: `src/client/shell/aggregate_navigation.rs` (仅此一个文件)
- **类型**: bug 修复 + 功能增强

## 问题 1: 搜索高亮定位错误

### 现象

在导航栏(`/` 唤出)搜索 `her` 后,列表只剩 `Config → Herdr → pane 1`,
但高亮落在父节点 `Config` 上,而不是匹配到的 `Herdr` tab。

### 根因

1. 输入搜索词时 `overlay_input.rs` 会把 `navigator.selected` 置为 `None`;
2. 渲染时 `navigator_selected_index()` 对 `None` 直接返回第 0 行;
3. 而过滤逻辑会把匹配节点的父链全部保留(workspace → tab → pane),
   所以过滤后的第 0 行永远是作为父节点保留下来的 workspace。

### 修复方案

`navigator_selected_index()`:搜索词非空且 `selected == None` 时,
对所有可见行的 label 打匹配分,选中得分最高的行。

**匹配质量分档**(用户确认的规则):

| 分数 | 匹配方式 | 例(查询 `her`)      |
| ---- | -------- | -------------------- |
| 5    | 完全相等 | `herdr`              |
| 4    | 前缀     | `Herdr`              |
| 3    | 词边界开头(按 `-`/`_`/空格/`.`/`:`/`/` 切词) | `my-herdr-app` |
| 2    | 包含     | `another`            |
| 1    | fuzzy 子序列(见问题 2) | — |
| 0    | 不匹配(父节点,仅因子匹配而保留) | `Config` |

**平局规则**(用户确认):

- 同分时取**行序最靠前**的行。由于树是先序遍历(workspace → tab → pane),
  这等价于"外层单位优先(workspace > tab > pane),同级取第一个"。
- 只匹配名字(label);路径/分支(meta)不参与高亮评分。
  meta 仅决定"行是否显示",meta-only 匹配的行 score 为 0,
  全部行都 0 分时回退到旧行为(第 0 行)。
- 搜索词为空、或用户手动 ↑↓ 选中(`selected = Some`)时,行为完全不变。

## 问题 2: 带空格的名字无法被无空格查询命中

### 现象

pane 名为 `pi config`,搜索 `piconfig` 匹配不到(过滤直接把它淘汰了)。

### 根因

原匹配是纯子串 `label.contains(query)`,`piconfig` 在 `pi config` 中不连续。

### 修复方案

1. `navigator_label_match_score()` 在"包含"档加入
   **fuzzy 子序列匹配**(`is_subsequence`):查询字符按顺序出现在
   label 中即可、允许跳空隙。`piconfig`、`pcfg` 均可命中 `pi config`;
   乱序(`configpi`)不命中,保持结果可预测。
2. `navigator_rows()` 的行可见条件从 `label.contains(query)` 换成
   `navigator_label_match_score(label, query) > 0`,
   过滤与高亮共用同一把尺子。

## 测试

`aggregate_navigation.rs` 内新增 `#[cfg(test)] mod tests`,共 10 个单测:

- `query_lands_on_matching_tab_not_ancestor_workspace` — 搜 `her` 高亮 `Herdr` 而非 `Config`
- `query_lands_on_workspace_when_only_it_matches` / `query_lands_on_pane_when_only_it_matches`
- `equal_score_prefers_outer_unit_then_first_sibling` — 同分外层优先、同级取第一个
- `match_quality_beats_row_order` — 匹配质量优先于行序
- `no_label_match_falls_back_to_first_row` — meta-only 查询回退旧行为
- `empty_query_and_explicit_selection_keep_old_behavior`
- `fuzzy_query_matches_pane_with_spaces` — `piconfig` / `pcfg` / 乱序拒绝
- `label_match_score_ranks_quality_tiers` — 分档边界


## 部署与回滚

- 本机无 zig,使用 `~/Downloads/zig-x86_64-linux-0.16.0/zig` 构建 release。
- 替换运行中的二进制时 `cp` 会报 `Text file busy`,
  改用 rename 语义绕过:`cp target/release/herdr ~/.local/bin/herdr.new && mv ~/.local/bin/herdr.new ~/.local/bin/herdr`。
- 修复只在 **client 端**,替换后 `ctrl+b q` detach 再重新 `herdr` attach 即生效,
  server 无需重启(协议未变),server 侧在下次重启时自然切换到新版。
- 旧版备份: `~/.local/bin/herdr.bak-pre-search-highlight`(高亮修复之前、fuzzy 之前)。
